# Research: touch-slicing-ui

Selected lanes (user-confirmed 2026-09-15): L1 catalog size, L2 engine defaults/capabilities, L3 G-code preview, L4 simple vs advanced tiers, L5 wanted features + adaptive app. Decisions so far: SolidJS, curated catalog + custom printer, 3D model viewer + G-code toolpath preview in MVP (Engram `sdd/touch-slicing-ui/decisions`).

L1 and L2 (source reading) are delegated to Codex and appended at the end of this file. L2 local engine probes were run by Claude and are below.

## L2 (local) — Engine capabilities and key behavior (Claude)

Real OrcaWasm patch19 single-thread engine in Node, 20 mm cube, base Ender-3 V2 + PLA profile with overrides.

`onewasm_get_capabilities`: API 0.2.0, OrcaSlicer 2.4.2, single-threaded runtime, `cancellationMode: cooperative`, init format `orca.native-json`, full profile `project.3mf`. Features supported: native/full-profile configuration, progress callback (not registrable from this JS build: no `addFunction`, fixed table), cancellation, statistics, single and multi slicing, auto-orient, arrange, OBJ→STL, CAD→STL, 3MF read/write.

| Probe | Result |
|---|---|
| Baseline | Effective defaults visible in the G-code header comments (`; key = value`): `brim_type = auto_brim`, `brim_width = 5`, `curr_bed_type = Cool Plate`, `sparse_infill_pattern = crosshatch`, `support_type = normal(auto)`. Estimate lines: `; estimated printing time (normal mode) = 27m 25s`, `; filament used [g] = 4.09` |
| `brim_type = no_brim` | Accepted (smaller G-code) |
| `layer_height = 0.12` | 166 layers, 42m 11s |
| `sparse_infill_density = 40%` | 5.72 g, 38m 33s |
| `wall_loops = 5` | 5.05 g, 31m 41s |
| `enable_support = 1`, `support_type = tree(auto)` | Accepted |
| `curr_bed_type = Textured PEI Plate` + `textured_plate_temp = 65` | `M190 S65` |
| `sparse_infill_pattern = banana` (invalid) | **Silently ignored** → crosshatch, no error |

Implications: the UI must validate enum values client-side; it can show effective settings by parsing the G-code header; time and filament estimates are available without extra API calls.

## L3 — G-code toolpath preview and model viewer

- [ChestnutLabs/gcode-preview](https://github.com/ChestnutLabs/gcode-preview): MIT fork, v0.20.1 released 2026-09-02 ([releases](https://github.com/ChestnutLabs/gcode-preview/releases)), near-weekly cadence, 7 open issues, three.js peer `^0.178`. Worker-based parsing, `ToolpathIR` with layer chunks, decimation and draw-range scrub, degradation pool → serial → lines. Native `<gcode-preview>` Web Component plus React/Vue/Svelte adapters; **no SolidJS adapter**, so use the Web Component. Bundle size unverified.
- [xyz-tools/gcode-preview](https://github.com/xyz-tools/gcode-preview): 202 stars, 58 open issues, MIT, three 0.166–0.186; no Web Component or SolidJS path confirmed.
- iOS Safari has a practical WebGL canvas memory ceiling of ~224–300 MB, stricter than reported texture limits, and exceeding it crashes the page ([Apple forums 112218](https://developer.apple.com/forums/thread/112218)).
- `three/webgpu` WebGPURenderer falls back to WebGL2 ([three.js manual](https://threejs.org/manual/en/webgpurenderer.html)); Safari/iPadOS 26+ has WebGPU, older versions use WebGL2.
- [camera-controls](https://github.com/yomotsu/camera-controls) gives iPad-friendly two-finger pan and pinch; OrbitControls needs three fingers to pan. TransformControls has reported touch issues (lower confidence), so plan a custom touch gizmo.
- OffscreenCanvas + WebGL2 in a worker is reliable on Safari 16.4+ ([caniuse](https://caniuse.com/offscreencanvas)).
- PrusaSlicer's G-code viewer is desktop C++ (AGPLv3), not reusable.

**Budget plan (iPad):** keep ~100–150 MB for toolpath geometry; lines by default, tubes only for the current or zoomed layer; GPU buffers only for visible layers. Estimate (unverified): 5 MB G-code ≈ 100–170k move lines, 50 MB ≈ 1–1.7M.

**Recommendation:** ChestnutLabs `<gcode-preview>` + three.js `STLLoader` + camera-controls + a custom touch gizmo. Prototype the Web Component inside SolidJS early and bench a 50 MB G-code on a real iPad.

## L5 — Features users want, browser constraints, adaptive app

Evidence of demand:

- Bambu Handy users ask for a quick mobile slicer (even just brim) and note the missing iPad landscape mode ([forum 101524](https://forum.bambulab.com/t/slice-and-send-to-printer-directly-from-bambu-handy/101524), [forum 76353](https://forum.bambulab.com/t/bambu-handy-add-brim-option/76353)).
- Prusa EasyPrint validates the category: Printables import, 3D preview, profiles, scale, multiples, pack plate, infill, auto supports ([Prusa blog](https://blog.prusa3d.com/prusa_easy_print_on_phone_tablet_110894/)), plus LAN send with manual protocol and IP and a download fallback for OctoPrint ([Tom's Hardware](https://www.tomshardware.com/3d-printing/prusas-mobile-slicer-now-works-with-competitors-3d-printers-new-easyprint-tool-works-with-bambu-creality-and-more)).

Browser constraints:

- Chrome gates HTTPS page → LAN HTTP requests behind Local Network Access ([Chrome](https://developer.chrome.com/blog/local-network-access)); Safari behavior unverified.
- Bambu LAN mode is MQTT+TLS with access code plus FTPS, not reachable with `fetch` ([Bambu wiki](https://wiki.bambulab.com/en/general/bbl-security)).
- `navigator.deviceMemory` is Chromium-only ([caniuse](https://caniuse.com/mdn-api_navigator_devicememory)).

| Feature | Tier |
|---|---|
| Import from Printables/MakerWorld/Thingiverse link (CORS/proxy risk) | MVP |
| Auto-orient + arrange | MVP |
| Quality presets + saved printer/filament profiles | MVP |
| Per-object brim / supports toggles | MVP |
| Time, filament and cost estimate (present in G-code) | MVP |
| Open from Files app | MVP |
| Offline PWA (Cache Storage eviction risk on iOS) | MVP |
| Scaling with units | MVP |
| LAN send to OctoPrint / Moonraker / PrusaLink | Next |
| Support painting / blockers, layer time, G-code thumbnails, slice history, dark mode, Apple Pencil | Next |
| Cut / split | Later |
| Bambu LAN printing | Out of scope for a browser-only app |

**Adaptive app:** one progressive-enhancement PWA using feature detection (`hardwareConcurrency`, `navigator.gpu`, viewport/pointer media queries) plus a user "Standard / Full" toggle, rather than two builds. No precedent found in this domain; reasoned recommendation.

Ideas (not evidence): on-device slicing explainer, share-sheet handoff to Bambu Handy / Prusa Connect, self-test before unlocking "Full", local slice history with thumbnails, manual IP LAN-send with download fallback.

### Flat-catalog sizing: estimates, not generated catalogs

The existing [local flat profile](../../../profiles/ender3v2-020-pla.json) was measured with Node `zlib.gzipSync`: **207 keys; 9,357 bytes raw; 2,530 bytes gzip** (27.04% of raw). Minifying produces 7,734 bytes raw / 2,467 gzip. These are local measurements of one Ender-3 V2 configuration, not upstream averages. URL-form local evidence: [profile](../../../profiles/ender3v2-020-pla.json); [resolver](../../../scripts/resolve-profile.mjs). Estimates below use the measured 9,357/2,530-byte pair and decimal MB. Other machines may carry longer G-code or additional extruder settings.

For scenario (a), interpret “one generic PLA/PETG/ABS filament” as **three combinations per printer**: one each for PLA, PETG, ABS. If only one of those materials is intended, divide estimates by three. A “printer” must be defined as either a model with one chosen nozzle or every instantiated machine/nozzle variant; these are different catalogs. The [Ender-3 V2 preset](https://raw.githubusercontent.com/OrcaSlicer/OrcaSlicer/v2.4.2/resources/profiles/Creality/machine/Creality%20Ender-3%20V2%200.4%20nozzle.json) demonstrates model/nozzle/default-process distinctions.

| Scenario | Number of flat combinations | Estimated raw / gzip | Qualification |
|---|---:|---:|---|
| (a) Actual top 10 vendors by machine-file count | `3 × P_top10` | `28,071 × P_top10` / `7,590 × P_top10` bytes | Ranking and selectable-printer count unavailable; no false numeric total |
| (a) Eight verified model registries, one nozzle and default process per model | 144 × 3 = 432 | **4.04 MB / 1.09 MB** | Model-level proxy, not top 10 and not all nozzle variants; assumes all three generic materials can be resolved compatibly |
| (a) Same proxy plus 13 directory-inferred Sovol models | 157 × 3 = 471 | **4.41 MB / 1.19 MB** | Adds unverified Sovol registry/selectability; still excludes Artillery |
| (b) Every selectable printer × every compatible process × generic materials | `sum over printers p and compatible processes q of G(p,q)` | `9,357 × combinations` / `2,530 × combinations` bytes | Compatibility graph not retrieved; if exactly three valid generic materials per pair, combinations = `3 × sum C(p)` |
| (b) Sensitivity example only: 1,000 printer/nozzle presets, 8 compatible processes each, 3 materials | 24,000 | **224.57 MB / 60.72 MB** | Assumed inputs, **not** a measured full-catalog size |
| Recommended six-vendor model-level budget, below | At most 112 × 3 = 336 | **3.14 MB / 0.85 MB** | Payload estimate excludes index/UI/assets; default nozzle/process and material compatibility still need build-time checks |

**Per-printer lazy files are recommended for initial transfer and bounded parse/cache work**, not asserted to have the smallest aggregate gzip. Put a small searchable model index in the app and lazy-load one model/nozzle package with its process/material combinations. Under the one-process/three-material assumption, a selected printer is approximately **28.1 KB raw / 7.6 KB gzip** using separately compressed-profile scaling, versus downloading all printers of that vendor. A vendor-wide file may compress repeated keys/G-code better and uses fewer requests; actual packed-vendor versus packed-printer gzip sizes were **not** measured. This is a design inference from the sizing model above, not an upstream performance claim.

### Curated recommendation and remaining gate

**Recommendation (not a completed selection): BBL, Prusa, Creality, Elegoo, Anycubic, and Voron**, using one validated default nozzle/process per supported model and compatible generic PLA/PETG/ABS. Their linked registries total **112 model entries**, giving a conservative single-profile-scaling budget of **336 combinations, ~3.14 MB raw / ~0.85 MB gzip**, plus the unmeasured small index. Start with the single-extruder/default-nozzle subset that passes engine smoke tests; leave multi-tool/mode variants unlisted until validated. Qidi, Sovol, RatRig, and Artillery can be added as separately tested lazy packs. This is a scope recommendation, not a popularity ranking.

Before claiming catalog completeness, retrieve the recursive tree (if truncated, walk `resources/profiles` by its returned subtree SHA); group blob paths matching `resources/profiles/<vendor>/(machine|process|filament)/*.json`, count and sum `size`, and sort machine counts for the top 20. Then fetch referenced preset files, resolve `instantiation` and compatibility metadata before counting selectable processes/filaments and computing scenario (b). Outstanding gaps: **tree bytes/counts/top 20; selectable process/filament counts; Artillery models; Sovol registry; shared-filament compatibility; actual packed-catalog gzip**. [Tree source to complete](https://api.github.com/repos/OrcaSlicer/OrcaSlicer/git/trees/v2.4.2?recursive=1).

`GCode::get_bed_temperature` picks first/later-layer key and filament/extruder index. First-layer temperature can use the initial filament or the highest used-filament temperature, depending on `bed_temperature_formula`. Start G-code containing M140/M190 suppresses automatic first-layer emission; macros receive the selected bed-temperature vectors. Later-layer transition uses the non-initial key. Therefore changing only `hot_plate_temp` will not change a Cool Plate print. Present advanced G-code edits with cross-field validation for E mode; do not silently “fix” a macro by switching extrusion mode. This is a design recommendation grounded in the source checks above, not an implemented feature.

**Remaining L2 gaps:** retrieve patch19 bridge initialization/parser/cancel/statistics construction code; verify all coercion and unknown-key cases; fetch `MaterialType::all()` suggestions; exercise real in-flight cancel in the deployed worker; validate multi-extruder/null-statistics semantics; audit desktop conditional visibility separately from mode metadata. Upstream schema values are not proof that the WASM build contains every same-tag feature unchanged.

### Key Learnings:

1. `comSimple` is the default metadata tier; literal assignments alone omit 86 common/FFF options, and generated keys add another 16 explicit simple options.
2. `adaptive_layer_height` is obsolete, while `brim_width=0` is the definition default—not the resolved profile's 5 mm.
3. Local patch19 slicing silently replaced the invalid infill enum and returned structured statistics; validate before sending and clear stale estimates after failure.
